# 长期记忆（Agent 启动即读）

> 放在**每次启动都会被注入**的位置。只写"长期有效"的规则，不写流水。

## 🔴 硬规则（违反即返工）

| 规则 | 为什么 |
|---|---|
| 写共享前先 `claim` | 两个 Agent 同时改必然打架 |
| 改完写总线，含**回滚点** | 没有回滚点的改动不算完成 |
| 关键数字写进 `what` 列 | 三个月后你是唯一读者 |
| 不手写总线表行 | 会被体检标出来 |
| 不预写 ID | 并发下会变，以工具返回值为准 |

## 判断口径

- **动手前**：「我要改的这个文件，属于哪条线？」→ 属于某条线就停手转交。
- **不确定时**：先自己查（读文件、跑命令），卡住再问 ——
  **目标是带着答案回来，不是带着问题回来。**
- **报告时**：结论先行，数字给真实值。

## 踩坑（别再踩）

- [ ] 分步"读 ID → 写文件"必撞号 → 整段放进原子锁
- [ ] 结构化匹配用 `^...$` 锚定，别用 `startswith`
- [ ] `0` 是假值 —— `code or DEFAULT` 会吃掉成功码
- [ ] 返回值不一定可信 —— 能验结果就别信返回码
- [ ] 写死的绝对路径，迁移后**静默失效**（不报错）
- [ ] 判据太严会天天假红 —— 假红比不报更坏
- [ ] 「写进文件」≠「通知到位」
