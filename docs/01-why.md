# 01 · 问题的形状

> 多 Agent 协作的失效，几乎从来不是"模型不够聪明"，而是**记录、边界、通知、判据**这四样东西坏了。

---

## 先说一个反直觉的观察

把两个能力相同的 Agent 放进同一个仓库干活，产出通常**远低于**两个独立任务的加总。
不是因为他们不会做事，而是因为他们在**互相污染对方的上下文**。

具体表现为四类失效。它们都不报错 —— 这是最麻烦的地方。

---

## 失效一：记录烂

共享日志是所有协作的地基。它坏掉的方式非常朴素：

- **撞号**：两个进程同时读到同一个"最大 ID"，各自 +1。
- **错位**：新记录被插进了历史记录之间（插入点算错）。
- **绕行**：有人直接编辑文件，格式和工具生成的不一样，解析器从此读不准。
- **失控增长**：单文件涨到几百 KB 之后，读它变成一件昂贵的事。

**为什么危险**：这些错误**不会抛异常**。你的程序照常跑，报告照常出，
只是数字悄悄错了。等到发现（比如"条数对不上"）时，往往已经积累了几十条。

> 对应教训：[01 ID 撞号](lessons.md#01--id-撞号分步读写的窗口期)、
> [02 插入锚被劫持](lessons.md#02--插入锚被正文劫持修工具的注释给工具埋了雷)、
> [03 手写行 vs 工具行](lessons.md#03--手写行-vs-工具行怎么一眼认出有人绕过了工具)

## 失效二：边界糊

"谁负责什么"如果只存在于口头约定，迟早会撞车：

- 两个 Agent 同时改了同一个文件 → 后写的覆盖先写的。
- 一个 Agent 顺手"优化"了别人的代码 → 越权且无人知晓。
- 出了问题追溯时，查不出是谁改的。

**为什么危险**：边界缺失不会让任务失败，只会让**质量悄悄下滑**，
并且每次都要花时间重新确认"这个该谁管"。

> 需要的不是更细的分工，而是**写下来的判据**：
> 什么产出归谁、什么情况下可以代劳、代劳之后要做什么。
> 见 [`03-seats.md`](03-seats.md)。

---

## 失效三：通知丢

这是最隐蔽的一类。

把一条信息"写进某个文档"之后，人们会默认"通知完成了"。
但真相是：

> **只有落在「对方每次启动都会自动读」的位置上，才算通知。**

一份要主动去读的注册表，只是**可查证**，不是**已通知**。
差别在于：前者在任何一次真实工作流里都不会被打开。

**为什么危险**：它在**几周后**才显形 —— 表现为"某个 Agent 一直在用过时的信息做事"，
而所有人（包括它自己）都觉得一切正常。

> 对应教训：[09 写进文件 ≠ 通知到位](lessons.md#09--写进文件--通知到位)、
> [05 只读镜像 = 信息孤岛](lessons.md#05--只读镜像--信息孤岛)

---

## 失效四：判据不可信

自动化检查是协作的免疫系统。但它有两种坏法：

- **太松**：放过真问题。撞号了但不报，行序乱了但不报。
- **太严**：天天假红。正常数据形态被判成错误 → 几周后所有人学会忽略告警。

**为什么危险**：第二种比第一种更致命。
**一个被忽略的告警，等于没有告警**，而且它还额外消耗了信任。

> 对应教训：[06 判据太严 = 天天假红](lessons.md#06--判据太严--天天假红)、
> [07 返回值会说谎](lessons.md#07--返回值会说谎判据只能落在结果上)

---

## 四类失效的共性

把它们放在一起看，会发现一个共同结构：

| | 表面现象 | 真实问题 | 为什么长期不被发现 |
|---|---|---|---|
| 记录烂 | 数字对不上 | 缺原子性 / 判据太松 | 不报错，只是慢慢错 |
| 边界糊 | 质量下滑 | 边界只在口头 | 没有"越界"这个事件 |
| 通知丢 | 信息过时 | 通知没有载体 | 偏差要几周才显形 |
| 判据坏 | 告警不响 / 总响 | 判据与数据形态不匹配 | 人已经学会忽略它 |

**共性 = 全都是"沉默的失效"。**

所以本项目的核心主张是：

> **对协作系统来说，「能自己发现自己在坏」比「一开始设计得完美」重要得多。**

这就是为什么本项目的重点不在"多聪明的调度算法"，而在一堆看起来很小气的检查：
ID 唯不唯一、行序对不对、插入点有没有被钓走、镜像多久没刷新了。

---

## 那要怎么做

三层，各解决一类问题：

| 层 | 解决 | 落地物 |
|---|---|---|
| **席位** | 边界糊 | 职责定义 + 边界判据（[`03-seats.md`](03-seats.md)） |
| **总线** | 记录烂 | append-only + 原子锁 + 写后自检（[`04-bus-protocol.md`](04-bus-protocol.md)） |
| **注入点** | 通知丢 | "每次都会读"的位置清单（[`05-injection.md`](05-injection.md)） |

外加一份**判据设计原则**贯穿始终（见 [`lessons.md`](lessons.md)）。
