# 05 · 注入点

> **"写进文件"和"通知到位"是两件事。**
> 一份写了但没人读的规则，等价于不存在 —— 而且更危险，因为**你会以为它生效了**。

---

## 一、判断标准只有一句

> **对方会自己读到吗？**

会 → 算通知。
不会（要主动去翻）→ 只是**可查证**。

这两者的差别不是"方便程度"，而是**在真实工作流里会不会发生**。
"要主动去翻"的位置，在忙碌的日常里**永远不会被打开**。

---

## 二、哪些位置算注入点

按"载体类型"分四类：

| 载体 | 什么时候进上下文 | 算不算通知 |
|---|---|---|
| **启动配置文件**（每次会话初始化时注入） | 每次启动 | ✅ 算 |
| **按需技能**（描述命中即加载） | 相关任务触发时 | ✅ 算 |
| **身份来源字段**（其他 Agent 判定"你是谁"时读） | 身份判定时 | ✅ 算 |
| **入口索引/手册/注册表** | 需要有人主动读 | ❌ **不算**（除非能证明每次都会读） |

> 一个实用技巧：给"入口文件"加顶部提示块（"开工先读这份"）+ 让上游流程强制引用它，
> 可以把它**提升**为准注入点。但这是**要维护的约定**，别忘了它依赖纪律而非机制。

---

## 三、标准动作：新成员接入清单

当你把一个新 Agent/新会话接入协作体系时，只写注册表 = **没通知**。
完整清单（按可执行顺序）：

### 第 1 步 · 定席位

明确它在席位体系里的位置（见 [`03-seats.md`](03-seats.md)）。
如果它就是"没有专属负责方"，**如实标注**（例如"由 XX 代管"），不要编一个出来。

### 第 2 步 · 写进「启动即注入」的配置文件

通常是这些文件（**若存在就更新，不存在就别造**）：

```
<agent-home>/IDENTITY.md     席位判定表
<agent-home>/SOUL.md         席位列表与语气
<agent-home>/USER.md         服务对象与分工说明
<agent-home>/MEMORY.md       长期铁律
```

> ⚠️ 这类共享文件**禁止写第一人称的席位名**（"我是 X 席位"）。
> 它们对所有会话生效，写死身份会**污染每一个读它的会话**。
> 正确写法：**"席位按工作区判定" + 判定表**。

### 第 3 步 · 按需技能（如果有）

有技能体系的运行时，把身份与接活入口写进**该 Agent 必读的那几个 SKILL**，
而不只是写进一个独立文档。

### 第 4 步 · 身份来源字段

有些运行时靠某个**存储字段**（比如数据库里的"人设"记录）判定 Agent 身份。
更新那里才算真正改了它的"自我认知"。

### 第 5 步 · 高频读的文件

入口索引 / 路由卡 / 快照顶部 —— 这些是**加分项**，不是替代品。

### 第 6 步 · 登记总线

先 `append` → **回读拿真实 ID** → 再把这个 ID 填进各文档。
> **绝不预写 ID**：并发下 `max+1` 会变，你先写的 "#216" 可能实际落在 #217。

---

## 四、同理适用于「规则变更」

改了规矩，但只写在一份手册里 → **没生效**。

| 变更类型 | 必须落到 |
|---|---|
| 身份/职责变了 | 启动配置文件 + 身份来源字段 |
| 流程变了 | 按需技能 + 入口索引 |
| 判据变了 | 代码 + 文档（两边都要，缺一不可） |

**自检问题**：*下次这个 Agent 启动时，会读到这条变更吗？*
不会 → 回第 2 步。

---

## 五、反模式

| 反模式 | 症状 | 修正 |
|---|---|---|
| **注册表幻觉** | "我登记了" → 实际没人知道 | 走完上面 6 步，别停在第 6 步的"写文档" |
| **只改工具不改说明** | 工具能做了，Agent 不知道有这个能力 | 能力要同时写进"按需技能"的入口 |
| **文档代替通知** | 手册写得很全，但没人读 | 手册只作为**补充**，不能作为唯一载体 |
| **第一人称污染** | 共享文件里写"我是 X 席位" | 改成判定表 |
| **预写 ID** | 文档里先写"见 #216" | 先 append，回读后再填 |

---

## 六、怎么验证"通知真的到位了"

**不要问"我写了吗"，要问"它读到了吗"。**

可操作的验证方式：

1. **新开一个会话**，什么都不说，看它是否已经知道这件事
   （能说出正确的席位名 / 正确的流程 → 通）
2. **让它复述规则**：能复述 → 注入生效
3. **检查实际读取记录**：如果运行时留下了上下文快照，
   直接看那次启动注入了什么

> ⚠️ 一个常见的假阳性：你**在对话里告诉过它**。
> 那不是"注入生效"，那只是"这次对话里它知道" —— 下次启动就没了。

---

## 七、一句话总结

> 通知有三个条件：**写对了地方、对方确实会读、你能验证它读到了。**
>
> 缺任何一个，都只是"我以为通知了"。
