# 15 · 接入指南（给你的项目用）

> 先回答一个问题：**你要的是「抄规矩」，还是「用代码」？**
> 两条路成本差 10 倍，收益也差 10 倍 —— **先选对，别一上来就全量**。

---

## 一、先做选择：三种接入深度

| 深度 | 你拿走什么 | 成本 | 什么时候选它 |
|---|---|---|---|
| **L1 · 抄规矩** | 只读 [`docs/`](README.md) 与 [`lessons.md`](lessons.md)，把纪律写进你自己的流程 / 提示词 | 半小时 | 你已经有协作工具，只是**记录会烂、单子会丢** |
| **L2 · 用总线**（**推荐起点**） | 加一份 `00-bus.md` + `wbb` 命令，所有交接走它 | 半天 | 你有多会话 / 多 Agent 真的在同仓库干活 |
| **L3 · 全量** | L2 + 资源租约 + 运行时迁移 + 体检脚本 | 1~2 天 | 你已经有**多个进程抢同一份稀缺资源**，或**长期会话会被反复重建** |

> ★ **最常见的选择错误是直接上 L3**：机制没错，但你的场景里没有对应的痛点，
> 于是它变成"要额外维护的规矩"，几周后被绕过 —— 这跟没接一样。

---

## 二、最快的一条路（15 分钟，L2 最小可用）

```bash
git clone https://github.com/WinterMK-byte/wb-bot && cd wb-bot

# ① 先确认环境没问题 —— 自测全过再往下走
python -m wbb.bus                 # 期望 20/20

# ② 在你自己的项目里建协作层
mkdir -p 我的项目/30_协作
cp templates/00-bus.md 我的项目/30_协作/00-bus.md
cp templates/01-seat-registry.md 我的项目/30_协作/席位注册表.md

# ③ 写第一条（格式：来源|角色|做了什么|状态|产物|需要谁）
python -m wbb.cli --bus 我的项目/30_协作/00-bus.md append \
  "我|架构|定了协作层落点|done|-|全员"

# ④ 体检
python -m wbb.cli --bus 我的项目/30_协作/00-bus.md verify

# ⑤ 设一次环境变量，之后不用每次带 --bus
export WBB_BUS=/abs/path/我的项目/30_协作/00-bus.md     # Windows: setx WBB_BUS "D:\...\00-bus.md"
```

**然后是关键的一步（不做这一步等于没接）**：
把你的**注入点文件**指向这份总线与席位表 —— 见 [`docs/05-injection.md`](05-injection.md)。

## 三、★ 你必须自己提供的东西（机制通用，参数是本地的）

这是**接入失败最常见的原因**：把通用机制搬过去，却指望它自动知道你的本地参数。
下表每一行都必须由**你**决定，本仓库给不了默认值：

| 必须本地决定的 | 举例 | 决定了什么 |
|---|---|---|
| **席位表** | 谁是判断者 / 谁执行 / 谁验收；几条业务线 | 边界判据、越界定义 |
| **注入点路径** | 你的 Agent 每次启动**自动读**的那个文件（提示词 / skill / 配置） | 「通知」是否真的送达 |
| **投递口** | `_inbox/<线>/` 有几个线、叫什么 | 派单落到哪儿 |
| **资源组清单** | 哪几个服务会互抢同一份资源（显存 / 端口 / 文件锁） | 租约层能不能拦住冲突 |
| **隐私词表** | 只属于你的品牌名 / 内部系统名 / 业务词 | 门禁能不能挡住"通用词表抓不到"的那类泄露 |
| **迁移的旧位置 / 新位置** | 你把数据目录从 A 挪到 B | `migrate audit` 扫什么 |

> 本仓库的通用词表**抓不到品牌名与业务词** —— 这是已记录的事实，不是待办。
> 所以第五行必须你自己填。

## 四、★ 三个「接了才算接上」的判据

不要凭感觉。<u>用这三条判</u>：

1. **冷启动测试**：找一个**没参与搭建**的会话（或人），只给它注入点，
   问它"你现在该干什么"。它能答上来 → 注入点通了；答不上来 → 你的规矩只写在文档里。
2. **一条不靠嘴的派单**：写一条 append，投递到收件箱 + 贴脸，**全程不说话**。
   对方真的动了 → 派单链路通了；需要你口头补一句才动 → 投递点不在"启动必读"里。
3. **一次搬家的收口**：`migrate audit` 跑到**零命中**。
   还有命中 → 还有地方写死了旧位置，搬家后会**静默读空**（不报错，被当成"今天没事"）。

## 五、反模式（照做会白干）

| 反模式 | 后果 |
|---|---|
| 抄了规矩但**没设注入点** | 等于没抄 —— 「写进一个文件 ≠ 通知到任何人」 |
| 一上来就上 L3 | 为不存在的痛点付维护成本，几周后被绕过 |
| 给总线加"更新 / 删除"操作 | append-only 是承重墙，破了它，前面所有判据都失效 |
| 判据设得比实际能力严 | **天天假红** → 所有人学会忽略告警，比不报更坏 |
| 让 Agent 自己定义席位 | 边界必须**人**来定；否则没有"越界"可言 |
| 把 `verify` 通过当成"没问题" | 它只查 ID / 行序 / 时间列 / 列数，**不查语义**（表格被空行截断它就查不出来） |

## 六、接入之后，日常怎么用

| 频率 | 动作 | 命令 / 文件 |
|---|---|---|
| 每条交接 | 追加一条（六要素齐全） | `wbb --bus … append "来源\|角色\|做了什么\|状态\|产物\|需要谁"` |
| 每天 | 体检一次 | `wbb --bus … verify` |
| 收尾 | 确认 ID / 行序 / 尾部一致 | 见 [`docs/04-bus-protocol.md`](04-bus-protocol.md) |
| 长期会话换代前 | 生成接续文本 | `wbb migrate render --identity … --bus …` |
| 搬完家 | 扫旧位置，跑到零命中 | `wbb migrate audit --root . --old <旧> --new <新>` |
| 抢资源前 | 先 acquire，不够就停手 | 见 [`docs/10-resource-lease.md`](10-resource-lease.md) |

## 七、最小的「可运行骨架」

```
你的项目/
├── 30_协作/                     ← 协作层（名字随你，只要全机唯一）
│   ├── 00-bus.md                ← 从 templates/00-bus.md 拷
│   ├── 席位注册表.md              ← 从 templates/01-seat-registry.md 拷
│   ├── _inbox/
│   │   ├── 线A/                 ← 派单投递口
│   │   └── _done/               ← 做完的搬走
│   └── _state/                  ← 锁文件、租约状态
├── 注入点文件                    ← ★ 只有 1 个，Agent 启动必读；指向上面
└── （你自己的代码）
```

**两个位置规则**（别搞混）：

- **总线本体留一处**，收件箱只放**指针** —— 两份本体必然不同步。
- **注入点最多两处**（每个运行时一处），且都要指向同一份席位表 —— 多了必然不一致。
