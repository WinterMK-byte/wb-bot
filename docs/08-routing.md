# 08 · 路由层

> [06](06-heterogeneous-agents.md) 讲了跨运行时怎么通讯，[07](07-seat-governance.md) 讲了席位怎么划。
> 这一篇解决一个更靠前的问题：**一句话进来，谁接？**

---

## 一、问题：新会话每次都"听不懂"

现象：同一句口语（"那个东西弄一下""帮我看看 XX"），
**老会话秒懂，新会话一脸茫然**。

根因不是模型笨，是**新会话缺一份映射表**：

```
口语  →  [ 归谁？ 用哪个现成资产？ 入口在哪？ ]  →  执行
                    ↑
              这张表不存在，就只能猜
```

"猜"的代价：接了不该接的活（越界）、该用的现成资产没找到（重复造）、
或者干脆回一句"请问您具体指什么"（老板最烦这个）。

> **路由层就是这张缺失的表。**

---

## 二、路由卡：一条口语 → 责任方 → 入口

最小形态是一张**只追加的表格**：

| 老板这样说 | 责任方 | 入口 / 现成资产 |
|---|---|---|
| "那个日程更新一下" | 线 A 负责人 | `…/line-a/schedule.md` + 发布脚本 |
| "磁盘满了" | 协调者 | 盘查脚本 `…/tools/disk_audit.py` |
| "这个评测跑一下" | 线 B 负责人 | `…/line-b/eval.py` |

**三条铁律**（写在卡的最上面）：

1. **不需要为分工新开任何会话** —— 资产与契约都在磁盘，任何会话读卡 + 读总线即可对齐
2. **不归你的活，写总线交接，不要硬做** —— 交接时末列写清"需要对方做什么"
3. **卡是唯一真源** —— 与别的文档冲突时，**以本卡的责任方列为准**

### 为什么"只追加"

因为老板会不断说出新的高频句式。
每出现一个新句式就**补一行** —— 路由卡越用越全，而不是需要重写。

---

## 三、两层路由：口语路由 + 域路由

实践中光有"口语→责任方"不够，还有第二层：**任务域 → 资产**。

| 层 | 回答 | 例 |
|---|---|---|
| **L1 口语路由** | 这句话**归谁** | "那个日程" → 线 A |
| **L2 域路由** | 这件事**用哪些资产** | 域 `scheduling` → 日程文件 + 发布脚本 + 打印脚本 |

**冲突处置**：L1 优于 L2。先用口语定位责任方，再由责任方按域路由找资产。

```
  一句话
    │
    ▼
  ┌─────────────┐  命中 → 责任方
  │ L1 口语路由卡 │
  └─────────────┘
    │ 未命中
    ▼
  ┌─────────────┐  按任务域分类 → 责任方
  │ L2 域路由表  │
  └─────────────┘
```

---

## 四、路由卡还要管"文件归属"

"这句话归谁"之外，还有"**这个文件归谁**"——
这是 [07 · 席位治理](07-seat-governance.md) 那条"动手前自检句"的查询依据。

所以路由卡上通常挂一张**归属表**：

| 资产 / 目录 | 归属 |
|---|---|
| 线 A 工作区 | 线 A 负责人 |
| 线 B 工作区 | 线 B 负责人 |
| 跨线总控 / 协调层 | 协调者 |
| 本机全局运维 | 协调者 |

> **判据**：归属表的作用是让"属于哪条线"**有唯一答案**。
> 如果一个资产两个地方都声称归自己，那是**架构缺陷**，要先修归属，而不是让两个 Agent 各自理解。

## 五、踩过的坑

### 5.1 没有唯一真源 → 两处口径打架

如果"归谁"这件事**两个文件里各写一份**，早晚不一致。
后果：两个会话按各自读到的版本行动 → 双口径事故。

→ 必须指定**唯一真源**，并在真源里显式声明：
「与 X 文件冲突时，以本件为准，并请在总线回报该冲突」。

### 5.2 路由表做成"大而全" → 没人维护

一开始就想穷举所有句式 → 表格巨大、更新慢 → 实际没人用。

→ 正确做法：**从实际出现的句式长出来**。
只追加，命中率低就先空着，遇到再补。**"够用且活"胜过"完整但死"**。

### 5.3 把"能力"当"归属"

"这个 Agent 能做到 X" ≠ "这件事归这个 Agent"。
能力描述（谁擅长什么）和归属（谁负责）是**两张不同的表**，混在一起必然扯皮。

→ 能力写进架构文档，**归属写进路由卡**。
