# 14 · 运行时迁移 —— 会话会被重建，接续时别丢东西

> **一句话**：执行方**一定会被重建**（上下文塞满 / 换代 / 重装 / 崩了）。
> 重建本身不可怕，**丢掉「它是谁」和「它在办什么」才可怕** —— 而且这两样**都不会报错**。
>
> 本篇讲三件事：**接续文本里必须有什么**（§三 render）· **搬完之后必须查什么**（§四 audit）
> · ★ **哪些东西会变、哪些不变**（§五 / §六 —— 迁移**反复出错**的根，含可进 CI 的门禁）。
> 可运行实现：`wbb/migrate.py`（`python -m wbb.migrate` 跑自测）｜门禁：`tools/migrate_check.py`。

---

## 一、先承认一个事实：执行方是**耗材**

任何长期运行的 Agent 会话，生命周期都**短于**它承担的工作：

| 触发重建的原因 | 典型信号 |
|---|---|
| 上下文塞满 | 开始忘事、重复问已经答过的问题 |
| 模型换代 | 强模型只留给规划，日常执行要降本 |
| 机器重装 / 换机 | 系统迁移、盘迁移 |
| 进程崩了 | 数据库损坏、端口被占、依赖升级 |

⇒ **「会话」是壳，「职责 + 在办事项」才是本体。**
把本体搬到新壳里，这件事叫**迁移**，必须是**流程里的一等公民**，不是意外处理。

> ★ **所以：一份描述协作架构的文档，如果没写迁移，就是不完整的。**
> 它描述了「谁该干什么」，却没说「谁换了个壳之后还该干什么」。

---

## 二、迁移必须携带的三样东西

按**丢失后果**排序：

| # | 携带什么 | 丢了会怎样 | 从哪来 |
|---|---|---|---|
| **1** | **身份块**（我是谁 / 职责 / 边界） | 开始干不属于自己的活；越界没人知道 | 一份短的 markdown，原样搬 |
| **2** | **在办事实**（最近 N 条流水） | 同一件事做两遍，或没人接着做 | 总线末尾 N 条 |
| **3** | **未闭口清单**（状态非「完成」的） | 「做了一半」那部分**彻底消失** —— 它是静默的 | 从上一步筛出来 |

**为什么必须显式列「未闭口」**：已完成的条目躺在流水里，一眼能看出成果；
**未完成的条目沉在中间，谁也不会主动去捞**。而它恰恰是唯一需要被接手的东西。

## 三、`render`：把上面三样拼成一份接续文本

```bash
python -m wbb.cli migrate render \
    --identity identity.md \
    --bus ./00-bus.md --tail 20 \
    --out ./接续文本.md
```

产物是**固定五节**（节标题写死在代码常量里，可被自测）：

| 节 | 内容 | 为什么有 |
|---|---|---|
| 一、你是谁 | 身份块**原样**搬入 | 边界靠这一节守 |
| 二、你在办什么 | 总线末尾 N 条（表格） | 接上下文，不是接故事 |
| 三、还没闭口的事 | 状态非「完成」的条目 → 复选框 | **唯一需要被接手的东西** |
| 四、迁移后必须先做的三件事 | 认领 / 审计 / 登记接续 | 把「读完了然后呢」写死 |
| 五、这份文件怎么用 | 什么时候读、什么时候重建 | 防它自己变成一份没人维护的旧文档 |

### 两条纪律

1. **生成物不手改。** 改了会在下次重建时被覆盖 —— 要改就改**源**（身份块 / 总线）。
2. **放对位置。** 接续文本要落在新会话**启动时真的会读到**的地方。
   *放在那儿但启动不读，等于没放* —— 这是本仓库里反复出现的一类失效，见交接纪律那篇。

> **身份块缺了怎么办**：工具**不会默默放过** —— 它会在产物里写一段
> 「未提供身份块文件，**这是一处缺口**」。缺一块就要显式地缺，而不是安静地空着。

## 四、`audit`：迁移**之后**，把指着旧位置的地方找出来

```bash
python -m wbb.cli migrate audit --root ./工作区 \
    --old <旧根路径片段> --new <新根路径片段>
```

退出码：`0` = 零命中 ｜ `8` = 有引用待处理。

### 为什么这件事**不能靠脑子记**

路径写死后，搬家会引发一类**不报错的故障**：

```
读一个不存在的文件  →  大多数程序不抛异常，返回空
空结果被当成「今天没事」  →  功能静默失效，没人发现
```

它比崩溃危险得多 —— 崩溃至少有人知道。

**扫的时候必须注意的四件事**（都在实现里）：

| 注意 | 为什么 |
|---|---|
| **跳过二进制**靠**探测 NUL**，不是靠扩展名 | 扩展名会骗人；`.md` 里也可能塞二进制 |
| **跳过超限大文件** | 一个几 MB 的日志会把扫描拖成分钟级，而它几乎不会是配置 |
| **跳过 `.git` / 缓存 / 构建目录** | 否则命中全是噪音 |
| **给 `--new` 就输出替换建议** | 「发现」不等于「能修」；把下一步写出来 |

### 收尾判据

**同一命令跑到零命中**，才算这次迁移收口。零命中之前，迁移都是**没做完**。

## 五、★ 会变的 vs 不变的 —— 迁移之所以反复出错的根

前三节讲了「**怎么做**」（render / audit）。但真正让迁移**一错再错**的，不是做法，
而是**没分清哪些东西会变**。

### 两类东西，待遇必须不同

| | **不变的（骨架）** | **会变的（指针）** |
|---|---|---|
| 是什么 | 规则、顺序、义务 —— 「**无论谁是执行方都成立**」的东西 | 实参：路径、会话 ID、席位在几号工作区、当前在办什么 |
| 例子 | 「开工先读身份文件」·「收尾必须登记总线」·「未闭口清单必须逐条认领」 | `2026-10-16-18-53-22` 这个目录 · 某台机器的绝对路径 · 「今天在办 #417」 |
| 生命周期 | 几乎不改 | **每重建一次就变一次** |
| 该放哪 | 主文件（可以传很多代） | **单独一份指针文件**，主文件只**引用**它 |
| 写死会怎样 | 无所谓 —— 它本来就不变 | ★ **静默漂移**：说明书还指着上一代的位置，读的人读了个空，而且**不报错** |

> ★ **一句话判据**：写下一个「路径 / 编号 / 数量」之前，先问一句
> —— **「它会不会变？谁在变它？」**
> 会变 → 不许进骨架，去指针文件登记。

### 为什么这是「根」而不是「一个 bug」

因为**写死的当时看不出问题**。第一代跑得好好的，问题只在**下一代**发生，
而下一代看到的现象是「**读不到内容**」，不是「**报错**」——
于是它会被解释成「今天没事」「这活干完了」，**没有人会去查**。

⇒ 这类失效**不靠判据就抓不到**（见下一节）。

### 一个具体的形状：路径不能当身份

本项目上线第一天就撞到：一份「席位总表」把**工作区路径**当成了席位的标识。

但 —— **工作区是「会话」的属性，不是「席位」的属性**。
每开一个新会话，运行时就开一个新的工作区目录（实测在一台机器上攒了 70+ 个）。
⇒「工作区 = 谁是谁」从根上不成立，那张表**下一代一定认不出自己**。

修法就是本节的三层：

1. **指针文件**（席位 → 历代工作区 + *真正的记忆在哪*）
2. **入口桩**（放进每个新工作区，刻意**不写死席位**，所以可以无脑复制）
3. **主文件只引用指针**，不记任何路径

## 六、★ 迁移四律 —— 把「记得」变成「查得到」

上节讲清了病因。这一节把它**变成可执行的判据**。

### 四律

| # | 律 | 一句话 | 反例（会踩的） |
|---|---|---|---|
| **一** | **会变的，不写死** | 骨架文件里**不许**出现实例形状（时间戳目录、机器绝对路径） | 席位表里写死 `2026-10-16-…` |
| **二** | **权威，只有一处** | 每样事实**只在一处**权威；其余地方只能**引用** | 席位表一份、记忆里又抄一份，改了一处另一处漂 |
| **三** | **入口，挂启动必读位** | 机制**落地 ≠ 送达**；必须挂在接收方**启动时真的会读到**的位置 | 改了 skill，没改那个每次启动都读的入口 |
| **四** | **形状与接线，必须分离** | 可复用的**形状**（机制）与某台机器的**具体接线**（路径/端口/密钥）分开；前者进仓库，后者留本机 | 把本机绝对路径混进通用工具里 |

> ★ 前三条**可机械判**，所以能进 CI（下一小节）。
> 第四条是**设计判据**，靠 review —— 它的自测是「把这个文件复制到另一台机器上，还成立吗」。

### 四起事故，形状一模一样

这不是理论 —— 以下四件事**在同一台机器上真实发生过**，而且事后看，**形状完全相同**：

| 事故 | 当时以为 | 实际 | 对应律 |
|---|---|---|---|
| 迁移能力**没写进 skill** | 「机制做完了」 | 机制在，但**没人读得到** | 律三 |
| 任务里**写死绝对路径** | 「配置好了」 | 搬家后每天**读空**，被当成「今天没事」 | 律一 |
| 流程规范**漏了迁移** | 「文档挺全」 | 描述了「谁干什么」，没说「**换壳后还该干什么**」 | 律四 |
| 席位总表**把自己钉在旧工作区** | 「表填好了」 | 下一代**认不出自己** | 律一 / 律二 |

⇒ **共同形状**：`路径被写死` / `权威有两份` / `入口没挂` / `形状与接线混着`。
⇒ **结论**：**靠「记得」防不住，靠「判据」才防得住。**

### 门禁：`tools/migrate_check.py`

把前三条变成一条命令：

```bash
# --index    指针文件（权威：一切会变的东西登记在这里）
# --skeleton 骨架文件（不许写死实例）
# --graft    启动必读位（必须真的含指向指针的字符串）
python tools/migrate_check.py \
    --index    seats.json \
    --skeleton SKELETON.md \
    --graft    IDENTITY.md --needle SKELETON
```

| 检查 | 判据 | 命中时退出码 |
|---|---|---|
| 律一 | 骨架里的实例形状**必须**在指针文件登记过 | `1` |
| 律二 | 指针文件里登记的每个路径**必须存在**（否则是**死指针**） | `1` |
| 律三 | 注入点文件**必须真的含**指针关键词 | `1` |

```bash
python tools/migrate_check.py --selftest   # 6 项自测（含 4 个反向用例）
python tools/migrate_check.py --demo       # 端到端演示（现场铺一份干净的，跑三项）
```

> ★ **刻意不报的两类**（判据太严 = 天天假红 = 人学会忽略告警）：
> **固定路径**（不含实例形状）不报 · **日期流水文件**（`2026-10-16.md`，是流水不是实例目录）不报。

**用法上的两点**：这项检查**第一次配**意义最大（它会把存量里的写死找出来）；
之后进 CI，每次改动都验一遍 —— 于是「迁移架构」从**靠人记得**，变成**机器守着**。

## 七、和别的东西什么关系

| 机制 | 管什么 |
|---|---|
| **本件（迁移）** | 换了壳之后，**怎么接着干** |
| 交接纪律 | 单子**怎么派才不丢**（投递 / 回执 / 验收） |
| 席位治理 | **谁该干什么**（边界 / 代劳） |
| 跨进程资源租约 | 多个壳**抢同一份资源**时怎么办 |

**一句话**：迁移负责「**接上**」，其余三件负责「**接上之后怎么不乱**」。

## 八、落地清单

- [ ] 给每条长期会话准备**身份块**（短，只写身份 / 职责 / 边界）
- [ ] ★ **把「会变的」全部挪进指针文件** —— 主文件里不留任何路径 / 编号 / 数量
- [ ] 每次重建前跑一次 `migrate render`，产物放进新会话的**启动必读位**
- [ ] 新会话读完，**在总线登记「谁接的、从哪接的」**（事实登记，不是请示）
- [ ] 迁移后跑 `migrate audit`，**跑到零命中**才算完
- [ ] ★ 把 `migrate_check` 接进 CI —— **迁移架构从此靠机器守着，不靠人记得**
- [ ] 把「未闭口清单」当交接正事办 —— 逐条认领，不认领的写明「我不接」
