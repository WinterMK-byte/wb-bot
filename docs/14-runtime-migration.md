# 14 · 运行时迁移 —— 会话会被重建，接续时别丢东西

> **一句话**：执行方**一定会被重建**（上下文塞满 / 换代 / 重装 / 崩了）。
> 重建本身不可怕，**丢掉「它是谁」和「它在办什么」才可怕** —— 而且这两样**都不会报错**。
>
> 本篇讲两件事：**接续文本里必须有什么**（render）· **搬完之后必须查什么**（audit）。
> 可运行实现：`wbb/migrate.py`（`python -m wbb.migrate` 跑自测）。

---

## 一、先承认一个事实：执行方是**耗材**

任何长期运行的 Agent 会话，生命周期都**短于**它承担的工作：

| 触发重建的原因 | 典型信号 |
|---|---|
| 上下文塞满 | 开始忘事、重复问已经答过的问题 |
| 模型换代 | 强模型只留给规划，日常执行要降本 |
| 机器重装 / 换机 | 系统迁移、盘迁移 |
| 进程崩了 | 数据库损坏、端口被占、依赖升级 |

⇒ **「会话」是壳，「职责 + 在办事项」才是本体。**
把本体搬到新壳里，这件事叫**迁移**，必须是**流程里的一等公民**，不是意外处理。

> ★ **所以：一份描述协作架构的文档，如果没写迁移，就是不完整的。**
> 它描述了「谁该干什么」，却没说「谁换了个壳之后还该干什么」。

---

## 二、迁移必须携带的三样东西

按**丢失后果**排序：

| # | 携带什么 | 丢了会怎样 | 从哪来 |
|---|---|---|---|
| **1** | **身份块**（我是谁 / 职责 / 边界） | 开始干不属于自己的活；越界没人知道 | 一份短的 markdown，原样搬 |
| **2** | **在办事实**（最近 N 条流水） | 同一件事做两遍，或没人接着做 | 总线末尾 N 条 |
| **3** | **未闭口清单**（状态非「完成」的） | 「做了一半」那部分**彻底消失** —— 它是静默的 | 从上一步筛出来 |

**为什么必须显式列「未闭口」**：已完成的条目躺在流水里，一眼能看出成果；
**未完成的条目沉在中间，谁也不会主动去捞**。而它恰恰是唯一需要被接手的东西。

---

## 三、`render`：把上面三样拼成一份接续文本

```bash
python -m wbb.cli migrate render \
    --identity identity.md \
    --bus ./00-bus.md --tail 20 \
    --out ./接续文本.md
```

产物是**固定五节**（节标题写死在代码常量里，可被自测）：

| 节 | 内容 | 为什么有 |
|---|---|---|
| 一、你是谁 | 身份块**原样**搬入 | 边界靠这一节守 |
| 二、你在办什么 | 总线末尾 N 条（表格） | 接上下文，不是接故事 |
| 三、还没闭口的事 | 状态非「完成」的条目 → 复选框 | **唯一需要被接手的东西** |
| 四、迁移后必须先做的三件事 | 认领 / 审计 / 登记接续 | 把「读完了然后呢」写死 |
| 五、这份文件怎么用 | 什么时候读、什么时候重建 | 防它自己变成一份没人维护的旧文档 |

### 两条纪律

1. **生成物不手改。** 改了会在下次重建时被覆盖 —— 要改就改**源**（身份块 / 总线）。
2. **放对位置。** 接续文本要落在新会话**启动时真的会读到**的地方。
   *放在那儿但启动不读，等于没放* —— 这是本仓库里反复出现的一类失效，见交接纪律那篇。

> **身份块缺了怎么办**：工具**不会默默放过** —— 它会在产物里写一段
> 「未提供身份块文件，**这是一处缺口**」。缺一块就要显式地缺，而不是安静地空着。

## 四、`audit`：迁移**之后**，把指着旧位置的地方找出来

```bash
python -m wbb.cli migrate audit --root ./工作区 \
    --old <旧根路径片段> --new <新根路径片段>
```

退出码：`0` = 零命中 ｜ `8` = 有引用待处理。

### 为什么这件事**不能靠脑子记**

路径写死后，搬家会引发一类**不报错的故障**：

```
读一个不存在的文件  →  大多数程序不抛异常，返回空
空结果被当成「今天没事」  →  功能静默失效，没人发现
```

它比崩溃危险得多 —— 崩溃至少有人知道。

**扫的时候必须注意的四件事**（都在实现里）：

| 注意 | 为什么 |
|---|---|
| **跳过二进制**靠**探测 NUL**，不是靠扩展名 | 扩展名会骗人；`.md` 里也可能塞二进制 |
| **跳过超限大文件** | 一个几 MB 的日志会把扫描拖成分钟级，而它几乎不会是配置 |
| **跳过 `.git` / 缓存 / 构建目录** | 否则命中全是噪音 |
| **给 `--new` 就输出替换建议** | 「发现」不等于「能修」；把下一步写出来 |

### 收尾判据

**同一命令跑到零命中**，才算这次迁移收口。零命中之前，迁移都是**没做完**。

---

## 五、和别的东西什么关系

| 机制 | 管什么 |
|---|---|
| **本件（迁移）** | 换了壳之后，**怎么接着干** |
| 交接纪律 | 单子**怎么派才不丢**（投递 / 回执 / 验收） |
| 席位治理 | **谁该干什么**（边界 / 代劳） |
| 跨进程资源租约 | 多个壳**抢同一份资源**时怎么办 |

**一句话**：迁移负责「**接上**」，其余三件负责「**接上之后怎么不乱**」。

## 六、落地清单

- [ ] 给每条长期会话准备**身份块**（短，只写身份 / 职责 / 边界）
- [ ] 每次重建前跑一次 `migrate render`，产物放进新会话的**启动必读位**
- [ ] 新会话读完，**在总线登记「谁接的、从哪接的」**（事实登记，不是请示）
- [ ] 迁移后跑 `migrate audit`，**跑到零命中**才算完
- [ ] 把「未闭口清单」当交接正事办 —— 逐条认领，不认领的写明「我不接」
