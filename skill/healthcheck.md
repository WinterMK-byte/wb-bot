# 协作层体检

## 何时用

- 刚改过协作层（`bus.py` / 总线文件 / 水位线）需要验收
- 怀疑总线被写乱：**ID 重号、行序错乱、时间列格式异常**
- 新人接手前，先确认底座是健康的

## 体检七项

| # | 检查 | 判据 |
|---|---|---|
| 1 | ID 唯一性 | 无重号 |
| 2 | 行序 | ID 单调（无 `343→342` 这类倒退） |
| 3 | 插入点 | 新条目落在**表格尾部**，不在中段 |
| 4 | 时间列格式 | 全部符合 `YYYY-MM-DD HH:MM`（野行铁证：只有日期无时间） |
| 5 | 列数 | 每行够列（**只查"不足"，不查"过多"** —— 正文允许含分隔符） |
| 6 | 水位线 | `.watermark.json` 的 ID ≤ 总线 max ID |
| 7 | 备份有效性 | 备份文件能解析、行数与主文件一致 |

## 命令

```bash
# 全量结构体检
python -m wbb.cli verify

# 只在 CI / 自动化里用：静默模式，退出码 0=干净
python -m wbb.cli verify --quiet
```

## 判定纪律

### 只查"列数不足"，不查"过多"

行格式是 `| ID | 时间 | 来源 | 角色 | 做了什么 | 状态 | 产物 | 需要 |`。
**"做了什么"这一列允许含 `|`** —— 所以标准行解析后可能**多于**预期列数，这是正常的。
只把"少于最少列数"当错误。

### 行序修复绝不改内容

`--verify --fix` **只修行序**，绝不修改任何单元格内容。
改内容 = 篡改历史 = 不可接受。

### 插入锚必须严格匹配

找"变更记录"标题位置时，锚正则是 `^##\s+变更记录\s*$`（**严格**）。
宽松匹配（`startswith("## 变更记录")`）会被**条目正文里的同名串**劫持 —— 详见教训 02。

## 红旗信号

| 信号 | 含义 |
|---|---|
| 出现只有日期没有时间的行 | **有人手写绕过了工具** |
| 新条目出现在表格中段 | 插入点计算错误，或手写 |
| 第二次 `archive` 永远失败 | 归档校验拿整个目录比对（见教训 10） |

## 配套

改动协作层之后：**登记 → 体检 → 备份**，三步缺一不可。
