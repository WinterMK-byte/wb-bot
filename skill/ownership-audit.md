# 会话归属审计

## 何时用

- 判断两个会话是否**重复劳动** → 要不要合并
- 查"**谁改的这个文件**"
- 会话流健康检查（如"打开会话老弹同一个问题"）

## 核心纪律：用实测，不用自述

**不要问会话"你管什么"** —— 它可能基于错误的自我认知回答。

**要看证据**：

| 证据源 | 说明什么 |
|---|---|
| 会话写入过的文件清单 | 它**实际**操作过什么 |
| 文件时间戳 ∩ 会话工作时间 | 谁在什么时候动了什么 |
| 工作区 memory / 日志 | 它自己记录的工作轨迹 |
| 总线条目 | 它登记过什么（**注意**：只登记过 ≠ 只干过） |

## 审计步骤

```
① 列出待审计的会话（及其工作区）
② 对每个会话：
   - 从会话记录里提取「写操作」对象（改了哪些文件）
   - 从文件系统取这些文件的 mtime
   - 交叉验证：时间戳在不在该会话的工作时段内
③ 画重叠图：两个会话的操作对象有交集吗？
④ 判定：
   - 交集为空 → 分工清晰
   - 交集非空 → 要么重复劳动，要么边界模糊
```

## 判定口径

| 现象 | 结论 |
|---|---|
| 两会话操作对象**完全无交集** | 分工清晰，**不必合并** |
| 有交集但职责不同 | 边界模糊 → 补一条书面契约 |
| 有交集且职责相同 | **重复劳动** → 考虑合并或划分边界 |

**注意**：即使两个会话"看起来都在管同一个业务域"，
也可能一个是**负责人**（出判断/方案），一个是**执行者**（跑腿/运维）——
那是**正常的分层**，不是重复。**先分清层，再判重复。**

## 常见坑

### 坑 1：把"碰过"当"属于"

某会话**偶尔**改过一次某文件 ≠ 那个文件归它。
判归属要看**路由卡的归属表**（唯一真源），不是"谁碰过"。

### 坑 2：孤儿提问

现象："打开某个会话就弹同一个问题"。
根因：会话流里有**未闭合的提问**（问了出去、没人答、状态卡住）。

→ 审计时把"有问无答"的条目单独列出来，逐个闭合。

### 坑 3：只信总线登记

总线是**交接**记录，不是**工作**记录。
某会话干了活但没登记 → 总线上看不到 → 会误判"它没干"。

→ 所以审计**必须以文件系统实测为主，总线为辅**。
